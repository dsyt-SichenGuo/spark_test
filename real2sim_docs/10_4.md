# October 4: Unitree G1 Walking in Reconstructed Environments

This document summarizes the currently visible additions relative to Git HEAD, excluding ignored files and changes to `.gitignore`. The additions focus on reconstructed asset integration and walking in static environments. The existing `run_unitree_g1_benchmark.py` and its internal tensor benchmark module are not part of these changes.

## 1. Added Files and Their Roles

| File or directory | Purpose |
| --- | --- |
| `scrpits/run_unitree_g1_usd_environment_walk_benchmark.py` | High-level entry point: selects the environment, controller, and initialization settings, validates assets, and launches a separate Isaac runtime process. The directory is spelled `scrpits` in the current repository. |
| `pipeline/spark_pipeline/autonomy/unitree_g1_environment_tensor_walk.py` | Internal tensor runtime: loads and clones static scenes, controls G1, tracks goals, evaluates success, and resets episodes independently. |
| `reconstructions/marble-1.1-static/` | Static Marble asset containing only the environment collision mesh, without people, animation, or replay cameras. This package displays collision geometry rather than the original Gaussian/SPZ rendering. |
| `reconstructions/gpt-v4-static/` | Static GPT-v4 shop asset retaining scene geometry, materials, and collisions, with people, replay animation, and cameras removed. |
| `reconstructions/marble-1.1-dynamic/`, `reconstructions/gpt-v4-dynamic/` | Original asset packages and inspection records, including baked human animation and replay cameras, for viewing and comparison. The static walking task does not load these packages. The GPT-v4 package also includes textures. |
| `reconstructions/inspect_usdc.py` | USD inspection tool that records scene hierarchy, bounds, animated attributes, physics attributes, and stage metadata, and generates `environment.json`. `inspect_usdc.py.orig` is a backup rather than an entry point. |
| `tests/test_unitree_g1_static_environment_walk.py` | Automated tests covering initialization combinations, resets, goal heading, ground support, cameras, lighting, static assets, and argument validation. |

Within each static asset directory, `environment.json` describes the USD file, environment root prim, units, and animation/collision information. `inspection/prim_inventory.json` provides scene prims and bounds for startup validation and position sampling.

## 2. Capabilities Added to the Existing Benchmark

- **Unified environment selection**: switch between static assets using `--environment marble|gpt-v4`, with a shared runtime. The runtime checks that assets contain no people, cameras, physics scene prims, or time-sampled animation, and confirms that collision geometry exists.
- **Three independent initialization settings**: initial XY position, initial yaw, and goal XY position each support random or manual selection, yielding eight combinations. All three default to random in both environments. Random values are resampled after each reset; manual values remain unchanged. Start and goal positions must be at least 3 meters apart, configurable through `--min-goal-distance`.
- **Arrival requires facing the goal**: the robot continuously tracks the direction from its current position to the goal. Success requires a distance of no more than 0.45 meters and a heading error of no more than 15 degrees; both thresholds are configurable. Turning near the goal is allowed without treating small position changes as a stall. When the robot and goal nearly coincide in XY, the episode's start-to-goal direction is used as the heading.
- **Ground-based spawn calibration for Marble**: the runtime reads the original collision triangle mesh, checks slope, support beneath the robot, and local height variation, and rejects unsupported positions. It automatically places the robot base 0.793 meters above the selected floor. Alignment uses a Z offset for the entire scene without modifying the original ground mesh. GPT-v4 currently uses the configured fixed spawn height.
- **Episode management and batched execution**: supports multiple environments, random seeds, episode lengths, and independent resets after success, falls, stalls, or timeouts. Control runs at 50 Hz using the existing WBT/Sport controllers. Task logic is implemented by the new `EnvironmentTensorTask`, without instantiating predefined task classes from `spark_task`.
- **Camera and indoor display fixes**: after initialization and resets, the camera is placed behind the robot along the start-to-goal line. In Marble, walls, ceilings, and scene bounds constrain camera distance and height. Interior fill lights, a camera fill light, and ambient lighting are added. SPARK's default ground plane and decorative grid are removed to prevent the grid from floating above the asset's floor.

The controller performs goal tracking; no global path planner has been added. Walls or shelves that block progress can trigger a stall reset.

## 3. Running the Walking Task

Run all commands from the repository root:

```bash
conda activate spark_isaac
```

### 3.1 Select an Environment with Fully Random Initialization

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py --environment marble
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py --environment gpt-v4
```

By default, execution continues until manually stopped. Use `--steps 300` to limit the total number of control steps.

### 3.2 Random and Manual Settings

Position arguments use asset-local XY coordinates in meters, excluding translations applied to cloned environments. Heading is specified in degrees: `0` faces +X and `90` faces +Y. Roll and pitch remain upright.

| Setting | Mode argument | Manual value argument |
| --- | --- | --- |
| Initial position | `--robot-position-mode random\|manual` | `--robot-position X Y` |
| Initial heading | `--robot-yaw-mode random\|manual` | `--robot-yaw-degrees DEG` |
| Goal position | `--goal-position-mode random\|manual` | `--goal-position X Y` |

Providing a value without a mode argument automatically selects manual mode. Explicit `manual` mode requires a value; explicit `random` mode cannot be combined with its corresponding manual value.

Fixed start position, random heading and goal:

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble --robot-position -0.2 -1.0
```

Fixed goal, random start position and heading:

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 --goal-position -4 -4
```

Fixed start position and heading, random goal:

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble --robot-position -0.2 -1.0 --robot-yaw-degrees 217.24
```

All three settings specified manually:

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 \
  --robot-position-mode manual --robot-position -4 -4 \
  --robot-yaw-mode manual --robot-yaw-degrees 90 \
  --goal-position-mode manual --goal-position 2 2
```

Manual coordinates must lie within the scene bounds. Marble also requires valid ground support. The legacy `--init-mode random|fixed-start|fixed-goal` argument remains supported.

### 3.3 Controllers, Batched Execution, and Command Preview

```bash
# Run four environments headlessly with the Sport controller
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 --policy sportsafe \
  --num-envs 4 --headless --steps 300 --episode-steps 150 --seed 42

# Validate assets and arguments and print the command without starting Isaac
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble --dry-run
```

The default controller is `--policy wbtsafe`. Alternatively, use `--policy-config UnitreeG1WBTSafePolicy` or `UnitreeG1SportSafePolicy`. These retain the existing controller names without adding a safety filter. The high-level entry point automatically starts the internal runtime; it does not need to be launched separately.

| Common argument | Purpose / default |
| --- | --- |
| `--sampling-bounds XMIN XMAX YMIN YMAX` | Sets the rectangle for random position sampling; by default, scene bounds are inset by `--wall-margin 5` meters |
| `--spawn-height Z` | Manually overrides the local base height after scene alignment |
| `--goal-tolerance` / `--goal-yaw-tolerance-degrees` | Position / heading success thresholds, defaulting to 0.45 meters / 15 degrees |
| `--camera-distance` / `--camera-height` / `--camera-lookahead` | Desired camera distance, height, and lookahead, defaulting to 3 / 2 / 1.5 meters; Marble adjusts these to fit the available space |
| `--interior-light-intensity` / `--camera-light-intensity` | Marble interior / camera fill light intensity, defaulting to 1600 / 1000; either can be set to 0 |
| `--interior-ambient-intensity` | Marble ambient lighting intensity, defaulting to 0.8 |
| `--world-dir DIR` | Overrides the selected environment's static asset directory; new assets also require suitable scene alignment settings |
| `--real-time` | Paces execution according to the control period |

## 4. Asset Inspection and Source Scene Viewing

Display the inspection tool's arguments:

```bash
python reconstructions/inspect_usdc.py --help
```

Inspect a specific source asset:

```bash
python reconstructions/inspect_usdc.py \
  reconstructions/marble-1.1-dynamic/marble-1.1-dynamic.usdc
```

The tool requires `pxr`; use `spark_isaac` or Isaac Sim's Python interpreter. It writes reports to the asset directory's `inspection/` folder and regenerates `environment.json`. The default inspection status is `needs_review`: automated inspection alone does not establish that animation playback has been visually verified. Arguments such as `--environment-prim`, `--people-prim`, and `--camera-prim` specify confirmed prim paths.

To view the original human replay, open the corresponding `*-dynamic.usdc` through **File → Open** in Isaac Sim, click **Play** to run the baked animation, and select `/ReplayCamera` for the source camera view. The people are animated mesh replays rather than robots controlled by physics.

## 5. Automated Tests

```bash
python -m pytest tests/test_unitree_g1_static_environment_walk.py -q
```

The tests primarily verify computation, sampling, assets, and configuration logic; they do not run a complete robot walking simulation. After reorganizing the files, the entry point's repository root calculation and the test import path were updated to match the current `scrpits/` layout.
