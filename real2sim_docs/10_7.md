# October 7: Unitree G1 Walking, Gaussian Visualization, and Video Recording

This document combines the reconstructed-environment walking features described in `10_4.md` with the subsequent Marble full-appearance integration, camera improvements, mesh lighting, CUDA startup fixes, and MP4 recording. It describes the current implementation and commands. The existing `example/unitree_g1/run_unitree_g1_benchmark.py` and its internal tensor benchmark runtime remain separate entry points.

## 1. Files and Responsibilities

| File or directory | Purpose |
| --- | --- |
| `scrpits/run_unitree_g1_usd_environment_walk_benchmark.py` | High-level launcher: selects assets, policy, initialization, camera, and recording settings; validates configuration; starts the internal Isaac runtime. The directory is spelled `scrpits` in this repository. |
| `pipeline/spark_pipeline/autonomy/unitree_g1_environment_tensor_walk.py` | Internal tensor runtime: loads static scene clones, controls G1 at 50 Hz, tracks goals, resets individual episodes, updates cameras and lighting, and submits recording frames. |
| `tools/marble_gaussian_compositor.py` | Decodes SPZ assets, aligns Gaussians to the collider, checks CUDA before Kit startup, renders GS, and composites robot/goal pixels using native depth and instance IDs. |
| `tools/environment_walk_video.py` | Shared MP4 recorder and native camera capture. The runtime imports it from `tools`; it is no longer located under `pipeline/spark_pipeline/autonomy/`. |
| `scrpits/view_marble_gaussian.py` | Optional browser preview of the original static SPZ appearance, without launching the walking simulation. |
| `reconstructions/marble-1.1-static/` | Pure static Marble collision mesh, used by both `marble` and `marble-full`. |
| `reconstructions/gpt-v4-static/` | Static GPT-v4 shop geometry, materials, textures, and collisions. |
| `reconstructions/marble-1.1-supermarket-full-appearance-1s-18s/` | Original full-appearance package: multi-resolution SPZ files, source collider GLB, and alignment metadata used by `marble-full`. Dynamic USD stages from this package are not loaded. |
| `reconstructions/marble-1.1-dynamic/`, `reconstructions/gpt-v4-dynamic/` | Source packages and inspection records, including human animation and replay cameras, for inspection and comparison. The walking task does not load these dynamic stages. |
| `reconstructions/inspect_usdc.py` | Inspects USD hierarchy, bounds, animation, physics, and metadata, and generates `environment.json`. The `.orig` file is a backup. |
| `tests/test_unitree_g1_static_environment_walk.py` | Tests initialization, goal heading, resets, assets, ground support, camera constraints, lighting isolation, GS alignment/composition, CUDA configuration, and video encoding. |

Static asset manifests specify the USD file, static root prim, units, and animation/collision information. `inspection/prim_inventory.json` supplies scene bounds for validation and sampling. The runtime rejects static roots containing people, source cameras, authored physics scenes, or time-sampled attributes, and requires collision geometry.

## 2. Environments and Shared Task Logic

| `--environment` | Main Isaac viewport | Additional visualization | Collision geometry |
| --- | --- | --- | --- |
| `marble` | Original static Marble mesh and G1 | None | Static Marble collider |
| `gpt-v4` | Static GPT-v4 shop and G1 | None | Static GPT-v4 collisions |
| `marble-full` | Same Marble mesh and G1 as `marble` | **Marble full appearance + G1** window with GS appearance and the simulated robot | Same static Marble collider as `marble` |

All three environments share the same initialization, controllers, arrival criteria, and reset logic. No dynamic human actors or replay animation are loaded.

Initial XY position, initial yaw, and goal XY position each independently support random or manual values. All three default to random, giving eight possible combinations. Random values are resampled after resets; manual anchors remain unchanged. Start and goal must be at least 3 meters apart by default.

The robot continuously tracks the heading from its current XY position to the goal. Success requires distance at most 0.45 meters and heading error at most 15 degrees. Turning within the goal radius is allowed without triggering a stall solely because translation is small. When the goal nearly coincides with the robot, the initial start-to-goal heading supplies the direction.

The runtime supports multiple scene clones and independent resets after success, falls, stalls, and timeouts. `EnvironmentTensorTask` implements these rules directly; it does not instantiate a predefined `spark_task` task class. The WBT/Sport controllers run at 50 Hz. Their historical `wbtsafe` and `sportsafe` names do not add a safety filter. No global path planner is included; blocked progress can cause a stall reset.

### Ground Calibration and Alignment

Marble sampling reads the original collider triangles and rejects unsupported positions, steep surfaces, holes, and excessive height variation beneath the robot's support footprint. Unless overridden, the base is placed 0.793 meters above the sampled floor. The scene receives its configured Z translation; the original floor vertices are not edited. GPT-v4 uses its configured fixed spawn height.

The default translations are 1.02 meters in Z for Marble and 1.47 meters for GPT-v4. SPARK's default ground plane and decorative grid are removed so they do not float above the asset floor.

For `marble-full`, SPZ positions, rotations, and scales use the package's `alignment.json` and the original RUB-to-Z-up collider conversion. Transformed source GLB vertices match the static USD collider within 1 micrometer. This verifies visual/collision coordinate consistency, rather than independently establishing metric scale against the source video.

## 3. Launching and Initializing the Robot

Run from the repository root:

```bash
conda activate spark_isaac

python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py --environment marble
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py --environment gpt-v4
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py --environment marble-full
```

The launcher starts the internal runtime automatically. Execution continues until stopped unless `--steps` limits the run.

### Independent Random/Manual Settings

Coordinates are asset-local XY values in meters, excluding clone translations. Yaw is in degrees: `0` faces +X and `90` faces +Y. Initial roll and pitch are upright.

| Setting | Mode argument | Manual value |
| --- | --- | --- |
| Initial position | `--robot-position-mode random\|manual` | `--robot-position X Y` |
| Initial heading | `--robot-yaw-mode random\|manual` | `--robot-yaw-degrees DEG` |
| Goal position | `--goal-position-mode random\|manual` | `--goal-position X Y` |

Supplying a value without a mode selects manual mode automatically. Explicit manual mode requires a value; explicit random mode rejects its corresponding manual value. Manual positions must lie within scene bounds, and Marble positions also require valid floor support. Legacy `--init-mode random|fixed-start|fixed-goal` remains supported.

```bash
# Fixed start; random heading and goal
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble --robot-position -0.2 -1.0

# Fixed goal; random start and heading
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 --goal-position -4 -4

# Fixed start and heading; random goal
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --robot-position -0.2 -1.0 --robot-yaw-degrees 217.24

# All three settings manual
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 \
  --robot-position-mode manual --robot-position -4 -4 \
  --robot-yaw-mode manual --robot-yaw-degrees 90 \
  --goal-position-mode manual --goal-position 2 2
```

### Controllers, Clones, and Command Preview

The default policy is `--policy wbtsafe`. Select Sport with `--policy sportsafe`, or use the registered names through `--policy-config UnitreeG1WBTSafePolicy` or `--policy-config UnitreeG1SportSafePolicy`.

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 --policy sportsafe \
  --num-envs 4 --headless --steps 300 --episode-steps 150 --seed 42

# Validate assets and print the runtime command without launching Isaac
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --dry-run
```

## 4. GS Visualization and Headless Execution

`marble-full` defaults to all 1.92 million Gaussians at 960×720. The main mesh viewport remains available for camera navigation; the GS window follows the same camera. The collider stays visible and retains its collision API. In the GS composition, an instance-ID mask removes environment mesh pixels from native depth, while robot and goal pixels are composited against Gaussian camera-Z depth.

Use a smaller appearance asset or image for a lighter preview:

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --gaussian-quality 500k --gaussian-resolution 640 480
```

`--gaussian-quality` accepts `full`, `500k`, `150k`, and `100k`. These options change visualization only, leaving collisions and task behavior unchanged. Static GS RGB/depth is cached when the camera and intrinsics do not change. Native robot frames continue updating; navigation, zoom, and clone/view changes invalidate the cache when needed.

Headless Marble-full simulation skips GS loading/rendering unless `--gaussian-snapshot` or `--record-video` is enabled:

```bash
# Physics/control only
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --num-envs 4 --headless --steps 300 --seed 42

# Render and save the final GS + robot image
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --headless --steps 65 --episode-steps 30 --seed 42 \
  --gaussian-snapshot /tmp/marble_full_walk.png
```

For multiple environments, the view initially selects environment 0 and switches to the first row being reset. Mesh/GS cameras and the Gaussian clone origin refresh together.

## 5. Fixed and Bounded Follow Cameras

Both modes retain the original initialization: the camera starts behind the robot on the start-to-goal line. Marble's initial view accounts for walls, ceilings, and scene bounds.

```bash
# Default: fixed view until the next reset
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --camera-mode fixed

# Stable following, with synchronized mesh and GS views
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --camera-mode follow
```

Following tracks robot XY and smoothly turns behind its heading, transitioning from the initialized start-to-goal view without an initial jump. World +Z remains camera-up. Body roll, pitch, vertical bobbing, and falls do not flip the view; a tumble retains the last stable heading. Height follows terrain changes smoothly. Each reset reinitializes the follow state.

Every follow frame is constrained to the selected scene's XYZ bounds. Marble additionally checks the robot-to-camera segment against mesh walls and the roof. The camera immediately retracts when its original orbit would leave the scene or cross an obstacle, then smoothly restores distance in open space. Staying inside takes priority over the initial calibrated distance. Checks use asset-local coordinates and restore the selected clone's translation afterward.

`--camera-follow-smoothing SECONDS` defaults to `0.35`; larger positive values give gentler turns and distance recovery. `--camera-clearance METERS` defaults to `0.18`, providing a margin from bounds and mesh surfaces. These camera modes work with all environments.

## 6. Marble Mesh Lighting and GS Isolation

The Marble mesh view retains the intensity-550 dome and adds the original corridor lamps from `manuscripts/run_unitree_g1_marble_walk.py`: four sphere lights with intensity 6000 and radius 0.35 at `(-7.5, -14, 1.25)`, `(-6, -11.5, 1.25)`, `(-4.3, -9, 1.25)`, and `(-2.5, -6, 1.25)`.

To illuminate areas beyond that corridor, mesh-only fill lights use the same intensity/radius at the existing 4×5 indoor light positions and at the active camera. Fill shadows are disabled. Light-link collections restrict these additions to the selected clone's environment mesh, excluding robots, goal markers, and other clones. The GS colors and renderer are unchanged. Existing interior, camera, and ambient illumination remain available; GPT-v4 lighting is unchanged.

The `--interior-light-intensity`, `--camera-light-intensity`, and `--interior-ambient-intensity` arguments control the existing shared fill/ambient settings. The additional mesh-only lamps use the fixed profile described above.

## 7. MP4 Recording in Every Environment

Add `--record-video` with any environment and either camera mode:

```bash
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --camera-mode follow --record-video

python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble --camera-mode fixed --record-video

python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment gpt-v4 --camera-mode follow --record-video
```

Output defaults to `./videos` relative to the launch directory. Timestamp and process ID prevent overwriting earlier recordings:

| Environment | Files per run |
| --- | --- |
| `marble`, `gpt-v4` | `<environment>_<camera-mode>_<timestamp>_<pid>_mesh.mp4` |
| `marble-full` | Matching `_mesh.mp4` and `_gs.mp4`, submitted together with equal frame counts |

Videos capture rendered scene content, including active-camera navigation in fixed mode, follow motion, and episode resets. Menus and window borders are not recorded. Frames are streamed to disk rather than retaining the whole video in memory.

Playback FPS defaults to `50 / render-every`, giving 10 FPS with the default render interval after render buffers become ready. `--video-fps` overrides playback rate; it does not increase the number of rendered frames. `--video-dir` selects another output directory.

```bash
# Finite recording with a custom output directory
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --camera-mode follow --record-video \
  --video-dir ./videos --steps 300 --seed 42

# Recording without opening a GUI; both views are still rendered
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py \
  --environment marble-full --headless --record-video --steps 100 --seed 42
```

Ctrl+C requests completion of the current paired frame and finalization of MP4 files before Kit shutdown. Closing the Isaac window or reaching `--steps` also ends recording. Recording mode replaces Isaac's force-exit interrupt handling, and the high-level launcher waits for the runtime to finish saving. Force-killing the process can leave incomplete MP4 files.

## 8. Dependencies, CUDA Startup, and Moving to Another Machine

Walking requires the existing Isaac/PyTorch/controller environment. GS visualization additionally requires CUDA-enabled PyTorch, a compatible NVIDIA GPU, CUDA compilation tools, Ninja, and `gsplat`. The tested `spark_isaac` installation uses Python 3.12, PyTorch 2.11.0+cu128, CUDA Toolkit 12.8, and gsplat 1.5.3. Recording uses OpenCV's `mp4v` encoder, already available in this environment. If OpenCV is missing elsewhere, install `opencv-python-headless` there.

GS CUDA compilation and a small rendering check run **before the Isaac window opens**, reporting progress every 15 seconds. Wait for `CUDA ready ...; starting Isaac Sim.` First-time compilation or changed compiler/architecture settings can take several minutes. Importing `gsplat` alone does not test the CUDA extension.

The runtime locates NVIDIA Conda's `targets/x86_64-linux` include/library layout using the current Python environment and supplies process-local search paths. It reads the selected GPU's compute capability rather than hard-coding RTX 4090. Invalid inherited `TORCH_CUDA_ARCH_LIST` values are replaced with that capability if supported by the installed PyTorch. Valid overrides are retained. `MAX_JOBS` defaults to 4 for compilation when not already configured.

These changes do not modify drivers, system CUDA installations, or the parent shell. A different machine still needs compatible dependencies and may rebuild the extension. A valid architecture override or CUDA path copied from the old machine can interfere with that setup. Clear stale overrides before launching in the new environment:

```bash
unset TORCH_CUDA_ARCH_LIST
unset CUDA_HOME
python scrpits/run_unitree_g1_usd_environment_walk_benchmark.py --environment marble-full
```

## 9. Common Arguments

| Argument | Purpose / default |
| --- | --- |
| `--environment` | `marble` (default), `gpt-v4`, or `marble-full` |
| `--steps` / `--episode-steps` | Total control steps (`-1`: unlimited) / episode timeout, default 12000 |
| `--num-envs` / `--env-spacing` | Scene clone count / spacing, default 1 / 20 meters |
| `--seed` | Reproducible initialization |
| `--sampling-bounds XMIN XMAX YMIN YMAX` | Random sampling rectangle; otherwise scene XY bounds are inset by `--wall-margin 5` meters |
| `--min-goal-distance` | Minimum start/goal separation, default 3 meters |
| `--spawn-height Z` | Overrides base height in aligned asset-local coordinates |
| `--goal-tolerance` / `--goal-yaw-tolerance-degrees` | Arrival thresholds, default 0.45 meters / 15 degrees |
| `--camera-mode fixed\|follow` | Fixed initialized view (default) or bounded stable following |
| `--camera-distance` / `--camera-height` / `--camera-lookahead` | Requested initial camera geometry, default 3 / 2 / 1.5 meters; Marble may reduce distance/height |
| `--camera-follow-smoothing` / `--camera-clearance` | Follow response time / boundary margin, default 0.35 seconds / 0.18 meters |
| `--gaussian-quality` / `--gaussian-resolution WIDTH HEIGHT` | Marble-full appearance asset / render size, default `full` / 960×720 |
| `--gaussian-snapshot PATH` | Final GS composite PNG; also enables GS rendering headlessly |
| `--record-video` | MP4 scene recording; Marble-full records mesh and GS together |
| `--video-dir` / `--video-fps` | Output directory (`./videos`) / optional playback rate (default `50 / render-every`) |
| `--render-every` | Render interval in control steps, default 5 |
| `--interior-light-intensity` / `--camera-light-intensity` | Existing Marble shared fill intensity, default 1600 / 1000; either may be zero |
| `--interior-ambient-intensity` | Existing Marble ambient setting, default 0.8 |
| `--world-dir DIR` | Override the static asset directory; a new asset also needs suitable alignment settings |
| `--isaac-device` / `--device` | Select the Isaac compute device; otherwise use AppLauncher's default |
| `--real-time` | Pace execution according to the control period |
| `--dry-run` | Validate and print the runtime command without starting Isaac |

## 10. Asset Inspection and Standalone Viewing

```bash
python reconstructions/inspect_usdc.py --help
python reconstructions/inspect_usdc.py \
  reconstructions/marble-1.1-dynamic/marble-1.1-dynamic.usdc
```

The inspection tool requires `pxr`; use `spark_isaac` or Isaac Sim's Python interpreter. It writes `inspection/` reports and regenerates `environment.json`. The default `needs_review` status does not establish visual verification of animation. Confirmed prim paths can be specified with `--environment-prim`, `--people-prim`, and `--camera-prim`.

For source human replay, open the corresponding dynamic USDC through Isaac Sim's **File → Open**, click **Play**, and select `/ReplayCamera`. These source people are baked animated meshes, separate from the static walking task.

For an optional SPZ-only browser preview, use a Python environment with `numpy` and `viser`:

```bash
python scrpits/view_marble_gaussian.py --quality 500k --port 8878
```

Open the printed local URL (default `http://127.0.0.1:8878`). `--check-only` decodes and validates without starting a server. This preview does not run G1 physics or the walking task.
