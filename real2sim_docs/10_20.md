# October 20: G1 Keyboard Walking in a Reconstructed MAtCha Environment

The new `reconstruction_walk` implementation loads a reconstructed hallway as a physical mesh environment, runs a Unitree G1 with either the WBT or Sport walking policy, and displays synchronized mesh and Gaussian views. Keyboard commands replace the previous goal-directed walking task. Falls trigger local reinitialization so the user can continue exploring.

The implementation adds separate launchers and modules and reuses the existing robot agent and policy weights. The reconstruction assets described in this document are limited to `reconstructions/office-hallway-matcha/`.

## 3. Launching

Run these commands from the repository root:

```bash
conda activate spark_isaac

# Current default: new Gaussian model and ratio1 mesh, with WBT.
./scrpits/launch_unitree_g1_reconstruction_walk.sh --policy wbt

# Explicitly select the old reconstruction.
./scrpits/launch_unitree_g1_reconstruction_walk.sh \
  --scene reconstructions/office-hallway-matcha/configs/old.json --policy wbt

# Select the new reconstruction with its standard mesh.
./scrpits/launch_unitree_g1_reconstruction_walk.sh \
  --scene reconstructions/office-hallway-matcha/configs/new.json --policy sport

# Select the new reconstruction with its ratio1 mesh.
./scrpits/launch_unitree_g1_reconstruction_walk.sh \
  --scene reconstructions/office-hallway-matcha/configs/new_ratio1.json --policy wbt
```

Either policy can be used with any of the three configurations. Select one policy per run; switching policies requires restarting the application. The task runs until stopped unless `--steps` sets a finite control-step count.

## 4. Keyboard Walking and Recovery

| Key | Action |
| --- | --- |
| W / S | Move forward / backward in the robot frame. |
| A / D | Turn left / right. |
| Q / E | Strafe left / right. |
| Space | Clear movement input and command velocity. |
| R | Reinitialize at a nearby supported location. |
| F9 | Start or stop the combined GS/mesh recording. |

Held keys produce bounded velocity commands, and releasing keys reduces the command smoothly. Limits are 0.12 m/s forward/backward, 0.08 m/s sideways, and 0.30 rad/s yaw. Acceleration limits are 0.30 m/s², 0.25 m/s², and 0.80 rad/s² respectively. Opposing keys cancel. Application focus loss clears input. After initialization or recovery, a 70-step warmup allows the robot to settle before movement commands are accepted.

WBT blends between its standing and locomotion experts. Sport uses its own recurrent policy. Each policy retains its own actuation settings and resets its internal state on recovery.

A fall is confirmed when the base remains less than 0.30 m above the local floor or tilts more than 60 degrees for eight consecutive control steps. Nonfinite poses and falling below the environment also request recovery. The task chooses the nearest prevalidated spawn within 2 m; otherwise it selects a candidate near the last stable position, with the initial candidate as the final fallback. Recovery resets robot pose and velocity, policy state, input, and the follow camera without restarting Isaac.

## 5. Mesh Preparation, Alignment, and Collision

Preparation fits a floor plane, uses the reconstruction cameras to orient the scene, and transforms the mesh into a metric Z-up simulation frame. Initial positions are checked for footprint support, local height variation, wall clearance, and overhead clearance. Source PLY files are preserved.

Metric scale is estimated from an assumed median recording-camera height of 1.55 m. It is not a measured calibration. Use `meters_per_unit` when a measured reconstruction scale is available, or update `camera_height_m` when the actual camera height is known. The old and new reconstructions produce different transforms and scales.

The full mesh is used for display. A separate collision mesh is generated by vertex clustering, retaining surviving surface triangles. The original infinite ground plane and decorative grid are removed. Collision simplification can change small features, so supported spawn checks do not establish reliable traversability everywhere.

Each configuration uses a separate cache under `log/reconstruction_walk/office-hallway-matcha/old/`, `new/`, or `new_ratio1/`:

| Generated file | Purpose |
| --- | --- |
| `visual.usdc` | Complete display geometry, colors, materials, and world transform. |
| `collision.usdc` | Static triangle collision geometry and contact material. |
| `collision.npz` | Collision vertices and faces for indexed surface queries. |
| `spawns.npy` | Prevalidated XY, floor height, and yaw candidates. |
| `alignment.json` | Gaussian-native to simulation-world similarity transform. |
| `prepared.json` | Source signatures, calibration, geometry counts, and preparation results. |

`runtime.py` references `visual.usdc` and `collision.usdc` into the Isaac stage. `backends.py` reads the Gaussian PLY in the CUDA worker and applies the corresponding inverse camera transform. Backend depth is converted to world-unit camera-Z depth before composition.

## 6. Synchronized Mesh and Gaussian Views

The mesh window shows the reconstructed surface and simulated G1. The Gaussian window shows the learned appearance with the same robot composited into it. Both use the same captured simulation state, follow-camera pose, and intrinsics. Native instance labels isolate robot pixels; depth comparison allows Gaussian surfaces to occlude the robot.

Gaussian rendering allows at most one outstanding request. State identifiers are checked, and results from before a reset are discarded. The two windows publish their matching frames together, although the displayed state can lag the latest physical state while rendering completes. The camera follows the robot and clips its position against nearby surfaces. It does not replay the training-camera trajectory or source video.

The mesh defaults to a neutral gray material so surface shape is easier to inspect. Enable source colors with `--mesh-color`, disable them with `--no-mesh-color`, or toggle **Mesh source colors** in the mesh window. Material overrides live in the USD session layer and do not rewrite the cached USD or source PLY. The robot appearance and GS appearance are unchanged.

Lighting defaults to a coefficient of 2 and includes a dome, camera lights, and mesh-only interior fill lights. Override it with `--light-scale`. Lighting changes affect the native mesh/robot rendering, not the learned Gaussian background.

Physics uses 5 ms steps and four substeps per control update: a 50 Hz simulation control period. The default submits a render every five control updates at 640 × 480. This describes simulation scheduling, not guaranteed wall-clock performance. Increase `--render-every` or reduce image dimensions if rendering is too expensive.

## 7. Compatibility Fixes and Asset Selection

Keyboard character events can contain strings instead of `KeyboardInput` enums. The callback now filters event types before reading the key, accepts enum and string key representations, and ignores text and repeat events. This fixes the repeated `'str' object has no attribute 'name'` error.

Cache generation imports standalone PXR to write USD files. Running it before Isaac in the same interpreter caused USD/PXR type conflicts on a cold cache. Preparation now runs in an independent Python process, including when `--force-prepare` is used, so Isaac can initialize its own USD libraries.

When changing reconstruction versions, match all three inputs: Gaussian model, mesh, and camera JSON. Different training runs can have different coordinate frames even when they use the same source video. Mixing the old assets with the new cameras was reproduced as `No clear supported spawn found`. The packaged configurations pair these inputs correctly.

## 8. Other Gaussian Methods

`matcha_2dgs` loads MAtCha 2DGS PLY files with their matching rendering source. `gsplat_3dgs` loads standard Graphdeco-style 3DGS PLY files, requiring three scale fields. A matching `.ply` extension alone does not make the formats interchangeable.

A custom backend can be registered through `register_backend()` or selected as `module:Class`. Its constructor receives the scene configuration, Gaussian-to-world alignment, and device. It must provide `count`, `render(camera_c2w_cv, K, width, height)`, and `close()`, returning RGBA uint8 and world-unit camera-Z depth. `gaussian.to_mesh` supports an optional similarity transform when the Gaussian and mesh were exported in different native frames.

```bash
# Prepare assets and inspect the selected scene without starting Isaac.
python scrpits/run_unitree_g1_reconstruction_teleop.py --dry-run

# Run the real selected policy weights without physics.

# Render a registered camera through the Gaussian CUDA worker.
python scrpits/run_unitree_g1_reconstruction_teleop.py --gaussian-smoke-test

# Exercise physical fall recovery in a bounded physics-only run.
python scrpits/run_unitree_g1_reconstruction_teleop.py --policy wbt \
  --headless --steps 500 --scripted-command 0.06 0 0 \
  --test-fall-at 150 --max-resets 3 --no-real-time
```

Validation performed in `spark_isaac` included 12 CPU test cases, real WBT/Sport weight inference and state resets, dual-view captures, and injected physical falls followed by recovery. A 320-step WBT dual-view run and a 350-step Sport physics run each recovered from an injected fall. The ratio1 mesh also completed an 80-step dual-view run after forced cache generation. The old asset pair completed an 80-step run with one fall and automatic recovery.

## 10. Manual MP4 Recording

Recording is optional and off by default. The Gaussian window provides **Start recording (F9)** and **Stop recording (F9)** controls; F9 performs the same action when the application is focused. Starting before the first synchronized image pair waits for that pair instead of recording incomplete or mismatched views. A second press cancels the pending request.

Each start/stop interval produces one MP4 with **GS on the left and mesh on the right**. The encoder receives the same paired images published to the two windows, including the robot. Window decorations, buttons, and the desktop are excluded. At the default per-view resolution of 640 × 480, the MP4 is 1280 × 480. Odd dimensions are padded at the outer edge.

```bash
# Manual start/stop with a chosen output folder and frame rate.
./scrpits/launch_unitree_g1_reconstruction_walk.sh \
  --video-dir log/reconstruction_walk/recordings --video-fps 30

# Optional automatic start after the first displayed GS/mesh pair.
./scrpits/launch_unitree_g1_reconstruction_walk.sh --policy wbt --record
```

Without `--video-dir`, files are saved as `gs_mesh_<UTC timestamp>.mp4` in the selected scene's cache `videos/` directory. The current default therefore writes to `log/reconstruction_walk/office-hallway-matcha/new_ratio1/videos/`. Each interval has a separate filename. The status label and console report the saved path. Normal application shutdown and Ctrl+C finalize an active recording.

Recording defaults to 30 FPS in wall time, independently of simulation time and Gaussian rendering throughput. A background encoder repeats the latest displayed synchronized pair between updates, preserving the real duration of the recording interval without accumulating a queue of video frames. This does not create additional rendered states. OpenCV provides the MP4 encoder in the existing `spark_isaac` environment. `--record` cannot be combined with `--headless` or `--no-gs` because both rendered views are required.

The recording checks run with `python -m pytest -q tests/test_reconstruction_walk.py tests/test_reconstruction_recording.py`. All 15 cases passed, including decoded left/right color order, playback duration, odd-size padding, repeated recording intervals, input validation, and starting/stopping through the renderer controls.

Actual GPU validation also completed a 120-step run recording a 1280 × 480 MP4, then another run exercising start, stop, and start again through the renderer's recording callbacks. The two intervals produced separate playable clips, and application shutdown finalized the active clip. Logs, decoded frame counts, and a sample MP4 are retained under `log/reconstruction_walk/recording-validation/`.
